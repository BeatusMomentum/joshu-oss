## Desktop float-window session (refresh)

Refreshing the ArozOS desktop no longer drops open apps. Overlay [`aroz-desktop-window-session.js`](../../arozos/web-overlays-vanilla/aroz-desktop-window-session.js) stores window URL/geometry/z-order (and min/max, jChat docked/floating) in `sessionStorage` and restores after init. Same-tab only; logout / account switch clears. See [`docs/design/README.md`](../design/README.md#float-window-session-restore-refresh).

## jWeb: idle shutdown + warm-on-open + scroll bridge

Keep `BROWSER_IDLE_TIMEOUT_MS=300000` (CPU) but relaunch Firefox when jWeb opens (`fit-viewport` / status warm). Default start URL is **`https://joshu.me/`**. Host wheel / Arrow / Page keys go through `POST /joshu/api/camofox/scroll` (`public/vnc-scroll.js`, rate-limited) because scaled noVNC + x11vnc often drop them. See [`hitl-camofox-notes.md`](../hitl-camofox-notes.md).

## jTerm: resize blink gate

PTY resize only on ≥4px host delta (200ms debounce) + stable scrollbar gutter. Live boxes load ArozOS volume `subservice/jterm/app/` — use `scripts/hotpatch-jterm.sh` when `dist/jterm` is ahead of the volume. See [`jterm-arozos-app.md`](../jterm-arozos-app.md).

## jChat: icon vs tray windows

jChat is no longer a singleton. The **desktop icon** (and `openModule("jChat")`) opens a new **floating** window with a fresh Hermes session. The **taskbar avatar** toggles one **docked** companion (`jp-jchat-docked`). **Undock** (title-bar ↗ or in-app) pops that docked window free; the next tray click starts a new docked session. Tray mic/VU stay on the docked iframe.

Doc: [`hermes-chat-arozos-app.md`](../hermes-chat-arozos-app.md#multiple-windows-icon-vs-tray).

Agent and jMail bodies that looked like plain text in clients (raw `**bold**`, non-clickable `https://…`) now convert via [`plainTextToSimpleEmailHtml`](../../packages/email-signature/src/joshuEmailSignature.ts) before Nylas send: paragraphs, lists, bold/italic/code, `[label](url)` and bare URLs, then the companion signature.

## Slack / Telegram session idle (30 minutes)

Hermes default is `session_reset.mode: none` (one continuous gateway chat until `/new`). Slack DMs were still carrying nine-day-old transcripts.

**Joshu box default:** Slack and Telegram **idle-reset after 30 minutes**. jChat (`api_server`) stays continuous. Override `JOSHU_HERMES_MESSAGING_IDLE_MINUTES` (`0` / `none` to disable). Implementation: [`hermesMessagingSessionReset.ts`](../../src/hermesMessagingSessionReset.ts) (config.yaml + `gateway.json` `reset_by_platform`).

## Headline: EA owner-reply child

Owner mail to the **agent Nylas** inbox with a non-meeting ask used to **file** correctly (`ea-mail-ingress` + blocked `mail_track`) and then sit forever: ingress cannot send, project tracks default-block, and `project-*` must not `nylas_send_message`.

**Fix (scheduling analog):** after filing, path **D** spawns a **ready** task on board **`ea-owner-reply`** (`kind: owner_reply`, skill **`ea-owner-reply`**). The worker does the ask, then **`nylas_send_message`** on that thread. Ingress stays send-free. `mail_create_track_task` still default-blocks (waiting on a counterparty).

| Piece | Detail |
|-------|--------|
| Eligibility | Nylas + `from` is owner + track + **not** scheduling path A; skip `owner_sent_update` ([`ownerReplyEligibility.ts`](../../src/ea/ownerReplyEligibility.ts)) |
| Create | Assignee → **ready**; thread_id dedup → `existing_thread`; **no** post-create block |
| Handoff | Later mail on the same thread → `owner_reply_handoff_task` (unblock if blocked) |
| MCP | `owner_reply_list_tasks`, `owner_reply_create_task`, `owner_reply_handoff_task` |
| REST | `GET/POST /api/ea/owner-reply/tasks`, `POST …/tasks/:taskId/handoff` |
| Boards | `ea-owner-reply` in `EA_KANBAN_BOARDS` + no-autodecompose patch set |
| Skill | [`ea-owner-reply`](../../integrations/hermes/skills/executive-assistant/ea-owner-reply/SKILL.md); playbook **2.20.0** path D |
| Test | `npm run test:owner-reply` |

**Out of scope here:** Gmail delete/trash opt-in, unblocking existing `mail_track` cards, global ready-task sweep, sends from `project-*`.

Spec: [`hermes-integration.md`](../hermes-integration.md#owner-reply-child-kanban-first-2026-08) · MCP table: [`connectors.md`](../connectors.md#connectors-mcp-http-8795).

## Voice dictation sessions (lists, notes, rambling)

Multi-pause dictation (website lists, meeting notes, rambling thoughts) used to fail: each VAD silence ended an **organic** turn, STT heard the chunks, but Hermes never wrote a file (patrick web-voice, 2026-08-21).

**Fix:** Realtime tools `start_dictation` / `finish_dictation` / `cancel_dictation`. Joshu buffers every user transcript while the session is active (organic speech suppressed), then one Hermes job formats and stores:

| Format | Use |
|--------|-----|
| `cleanup` | Lists / light edit (normalize URLs, bullets, dedupe) |
| `reformulate` | Meeting notes / rambling → clear prose |
| `auto` | Hermes chooses from content |

Done via `finish_dictation` or a clear done phrase (*that's it*, *I'm done*, …). Browser + PSTN.

| Piece | Detail |
|-------|--------|
| Buffer | [`dictationSession.ts`](../../packages/voice-realtime/src/dictationSession.ts) |
| Tools / prompts | [`realtimeTools.ts`](../../packages/voice-realtime/src/realtimeTools.ts), [`joshuIdentity.ts`](../../packages/voice-realtime/src/joshuIdentity.ts) |
| Orchestration | [`browserRealtimeSession.ts`](../../packages/voice-realtime/src/browserRealtimeSession.ts), [`twilioRealtimeSession.ts`](../../packages/voice-realtime/src/twilioRealtimeSession.ts) |

Doc: [`voice-think-speak.md` — Dictation sessions](../vps-sandbox/voice-think-speak.md#dictation-sessions-lists-notes-rambling).

## last30days: honest engagement, Watching, X via xquik, QueryPlan

Research Results no longer show mixed `{n} eng`. Cluster cards use per-source native units and sort by relevance then log-comparable engagement. **Watching** (renamed Watchlist) is a business-user list + vs-average watch report (7d window, ≥3 runs). Fleet X search uses **xquik CP relay** (`POST /api/instances/xquik/proxy`); self-host pastes `XQUIK_API_KEY`. Store/Briefings/Doctor moved under Settings.

**Watching cron (fix):** Joshu boot now calls `syncAllAppManifestCronJobs` and writes no-agent scripts into `~/.hermes/scripts/`. Daily watches run at 08:00 local via Hermes job `last30days: watchlist daily`; weekly on Mondays. Previously the manifest job was never registered and `last30days-watchlist-run.sh` did not exist.

**jChat Watching tools:** `joshu-last30days` plugin now registers `last30days_watch_list` / `_add` / `_remove` / `_report` / `_run` / `_run_all` (same invoke contract as `last30days_research`). Skills `last30days-chat` and `last30days-gui` tell the agent when to call them.

**Writing style (saved brief):** Results stays JSON cluster cards. The `.md` under `research/last30days/` now applies the same audience register as upstream `--register` (exec / dev / creator / eli5): section order, cluster budget, source emphasis. Engine JSON emit still ignores register.

**Clustering / Results ordering:** Joshu patches `cluster.py` (lower similarity threshold for opinion/comparison). The GUI and saved brief sort by **relevance** then engagement; items below a **0.45** `relevance_score` floor are filtered when scores exist; event topics also drop other-city Tech Week hits. See [`agentReportFormat.ts`](../src/last30days/agentReportFormat.ts).

**Persistent last30days state:** Runs, query plans, plan-runtime, watch snapshots, Settings (`config/.env`), engine store (`share/research.db`), and memory live under `{AROZ_DATA}/files/users/<user>/.joshu/last30days/` ([`statePaths.ts`](../src/last30days/statePaths.ts)) on the `joshu_arozos` volume — they survive fleet `force-recreate`. Legacy `/opt/joshu/.joshu/last30days` and XDG homes (`~/.config/last30days`, `~/.local/share/last30days`, `~/Documents/Last30Days`) are migrated once on boot. Engine `store.py` honors `LAST30DAYS_SHARE_DIR` via [`patch-last30days-share-dir.py`](../scripts/patch-last30days-share-dir.py).

**Host-side QueryPlan:** [`src/last30days/queryPlan.ts`](../src/last30days/queryPlan.ts) classifies topics (named entity / **event** / concept / comparison), builds a JSON plan via **OpenRouter for every class** (heuristics fallback), and passes `--plan` before every research and watch run. Concept and **event** topics exclude TikTok/Instagram/**jobs** via `--search=`; named entities pin a social+web allow-list without jobs unless the topic is hiring. Trailing calendar years are stripped from the primary quote. Host-planned runs clear Simple/`--quick` so the engine does not collapse to one subquery and drop X. Plans persist on `watchingAdd` for cron replay. GUI, jChat, and plugin tools stay topic-only — skills `last30days-chat` 0.3.0 / `last30days-gui` 0.4.3 document automatic planning for Hermes.

Docs: [`last30days-user-guide.md`](../last30days-user-guide.md) · [`last30days-arozos-app.md`](../last30days-arozos-app.md#queryplan-host-side--transparent-to-gui--jchat) · [`hermes-integration.md`](../hermes-integration.md#joshu-last30days-plugin).
